# 本机开发入口与默认分仓规则

Routing Standard: v1.0.0；负责人确认日期：2026-10-02。
适用于 D:\Dev 下的新项目分配及日常开发；本文件不是 Git 仓库，不含账号凭据。

1. 开发前先读 D:\Dev\small-tools\docs\PROJECT_ROUTING_STANDARD.md，再读目标仓库的 AGENTS.md、docs/REPO_STANDARD.md 和项目文档。
2. 新项目先按功能边界、模块/数据复杂度、独立部署发布及维护需求判断大小，记录结论和依据；不机械按代码行数或安装包体积判断。
3. 小项目进入 w64828992-ops/small-tools 的 <software-name>/，本地 D:\Dev\small-tools\<software-name>。
4. 大项目建立 w64828992-ops/<project-name> 独立私有仓库，本地 D:\Dev\<project-name>；根据软件需求建立专用规则、说明、测试和 CI，不照搬多工具目录或旧业务架构。
5. 独立项目使用 README、AGENTS、主规则、开发/安全、需求与验收文档；架构、数据库、接口、部署/回滚等按需补充，不搭无用框架。
6. 所有自行维护的源码、脚本和测试必须有中文文件说明、类/函数/方法说明及关键逻辑原因注释；未满足不能交付。注释质量人工检查，明确语言自动检查的覆盖边界。
7. 保留中文注释、业务规则确认、测试、文档、版本判断、敏感信息扫描、PR、实际 CI 通过、合并及交付记录的闭环；失败或未执行不得称已完成。
8. 常规分仓/建私有仓库/归档按任务授权直接执行，无需反复询问；用户指定仓库或仅分析/不上传等限制优先。未知需求如实记录，不编造业务决策。
9. 修改现有项目先核对原 remote 和工作区；不迁移、删除、覆盖已有项目，不改全局 Git/账号配置，不把 D:\Dev 初始化成总仓库。
10. 小项目长大需要迁移时先列计划、历史与依赖，再确认实际迁移。OUTsoft 与 huiyun-ems 保持现有独立仓库，不接收无关小工具。
11. 仓库默认私有；公开、加人、付费、开源许可、生产访问/部署和破坏性动作另需明确授权。凭据不入 Git，不强推、不重写 Tag、不切断远程控制。
12. 无关文件与账号凭据不读取；对权限不足、扫描/测试失败、业务口径或历史数据风险停止相应发布并报告。
