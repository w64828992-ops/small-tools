# 汇云局域网跨传 - 安全说明

**Version: 1.0.0**
**Security Level: S2**

## 威胁模型

软件面向公司、家庭等可信局域网使用，不把公共互联网作为可信边界。

主要需要防止：

- 互联网来源直接访问接收服务；
- 未经接收方同意就写文件；
- 构造路径写到保存目录之外；
- 上传 offer 中没有声明的文件；
- 通过文件大小欺骗制造不完整文件；
- 同名文件被静默覆盖；
- 真实凭证进入日志或 Git。

## 身份与授权

### 设备能力凭证

每次应用启动生成 256-bit 随机 capability token。

- token 仅在当前进程生命周期有效；
- 通过局域网 discovery beacon 提供给附近设备；
- HTTP 请求必须携带目标电脑 token；
- token 不写入日志和设置文件。

它用于阻止不知道当前 capability 的盲目 HTTP 请求，但**不等同于加密身份协议**。界面显示的电脑名称也是提示信息，不是经过密码学认证的真实身份；因此本工具的信任边界始终是“可信局域网 + 接收方人工确认”。

### 人工授权

即使 token 正确，发送方也只能创建 offer。

真正上传文件前必须满足：

1. 接收端界面显示发送方电脑名称；
2. 接收用户点击接收；
3. 接收用户主动选择保存位置。

拒绝、过期、未确认的 offer 不能上传文件。

## 网络边界

接收服务仅允许：

- loopback；
- RFC1918 IPv4；
- IPv4 link-local；
- IPv6 loopback / link-local / ULA；
- IPv4-mapped IPv6 的上述范围。

公网来源返回 403。

## 文件系统保护

接收端：

- 对每个 manifest 路径重新校验；
- 禁止绝对路径；
- 禁止 `..`、`.`、空路径段和 NUL；
- 解析后的目标路径必须仍在用户选择的保存目录中；
- 只接受 expected-file map 中存在的文件；
- `Content-Length` 必须与 manifest 文件大小完全一致；
- 临时写入 `.part` 文件；
- 完整写入后才 rename；
- 顶层目标存在时自动生成 `(1)`、`(2)` 等新名称；
- symlink 不跟随。

## 日志

不得记录：

- capability token；
- 文件内容；
- 文件二进制数据；
- Authorization/Cookie/密码等真实凭证。

## 已知限制

### 没有端到端加密

v1.0.0 使用可信局域网明文传输。

同网段抓包者理论上可能看到：

- discovery beacon；
- capability token；
- 文件数据。

因此：

> 不要在机场、酒店、咖啡店等不可信公共网络上传输敏感资料。

未来版本如果需要在不可信网络中使用，应增加设备配对、TLS/Noise 等经过审计的加密协议，而不是自行设计加密算法。

### 没有断点续传

网络中断后需要重新发起传输。未完整写入的 `.part` 文件不会作为正式文件交付。

## 安全测试

当前自动测试覆盖：

- LAN / 公网地址判断；
- path traversal 拒绝；
- 顶层重名避让；
- 文件/空目录 manifest；
- symlink 跳过；
- 错误 token 拒绝；
- localhost 真实 HTTP 文件和文件夹端到端传输。

GitHub PR 和 main 同时执行仓库 Secret Scan。
